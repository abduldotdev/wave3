# Spec: Wave:3 remembered hardware settings, restore on reconnect, and busy-safe hardware access

Run `20260929-004215-1d0b-master`, slice `sup-1`. Part A is the settings store and restore. Part B is the addendum: `EBUSY` flicker in the popup.

## Problem

**A. Settings are lost on every power cycle.** The Wave:3 keeps its 16-byte vendor config block in volatile memory. Wave Link re-applies the block on Windows and macOS, but nothing does that here. The objective recorded this on the live mic (API 5.3):

```
before replug: 00 0a 00 ec 00 01 01 80 eb 00 00 00 01 00 00 01   gain 10 dB, lowcut 1, dial 1, gain_lock 1
after  replug: 00 28 00 ec 00 01 00 80 eb 00 00 00 02 00 00 00   gain 40 dB, lowcut 0, dial 2, gain_lock 0
```

- `bin/wave3-hw` has only `status` and `set` (`bin/wave3-hw:523-545`). It keeps no record of the user's choices.
- `bin/wave3-watch` only runs `wave3-reset --ensure-default` at start and on `new` source/card events (`bin/wave3-watch:14-21`). It never touches the hardware block.
- With `gain_lock=0` after power-on, the `SET_CUR` from ALSA/WirePlumber state restore (`Mic Capture Volume` 80/80, +40 dB) probably drives the gain to 40 dB. That write can arrive after the card appears, so a single write when the card appears can be overwritten.
- The dial byte (offset 12, `volume_select`) was seen changing 2 → 1 with no write. The dial reverts by itself, so it must never be restored.

**B. The popup flickers to the "no access" view.** The orchestrator reproduced this live. With 20 parallel `bin/wave3-hw status` runs, 15 printed `error=[Errno 16] Device or resource busy` (rc 0). With 40 sequential runs, all 40 printed `access=ok`.

- `cmd_status` (`bin/wave3-hw:420-457`) does not take the `file_lock()` that `cmd_set` takes (`bin/wave3-hw:471`), and no USB operation retries on `EBUSY`.
- `Model.parseHwStatus` (`Model.js:59-126`) derives `hwReady` from `present && access === "ok" && supported`. An `error=` output has no `present` line, so it parses as absent. `Widget.qml:153` replaces `root.hwStatus` with that result, and the popup switches to the setup/fallback view (`Wave3Popup.qml:572`) until the next poll.
- Where the contention comes from: one `Widget` per bar (3 monitors), each polling both `wave3-reset --status` and `wave3-hw status` every 10 s (`Widget.qml:232-238`) and every 3 s while its popup is open (`Widget.qml:240-245`). Popup `set` writes add to that, and so will the `wave3-watch` apply.

## Scope

### In scope
- A settings store file with atomic writes. Recording happens on a user change (`wave3-hw set` or the popup).
- New `wave3-hw` subcommands `apply`, `save` and `forget`, and a `saved=` line on `set` output.
- `apply`: one read-modify-write of the whole block, only for fields that differ, with read-back verification. Optional settle re-verify rounds guard against a late ALSA `SET_CUR`.
- `wave3-watch` runs `apply` at start and when a card/source appears, rate-limited, with one journal line per run. An apply failure never stops the watcher.
- Popup: a short "Saved · restores on reconnect" hint after a successful saved change.
- B1: every `wave3-hw` device access takes the one lock, and USB operations retry on `EBUSY`/`EAGAIN` with bounded backoff.
- B2: `status` reports transient failure as `error=busy` (or `error=<msg>`). Model and widget keep the last good hardware state on a transient error.
- B3: less polling. Closed-popup instances poll hardware rarely, and nothing polls hardware while a write is in flight.
- Tests (fake transport, stub watcher, Model), README, and `docs/link-sh-changes.md`.

### Out of scope
- Persisting or restoring `mute` (policy in B-5), `volume_select` or `raw`.
- Restoring pactl/PipeWire volume or mute. Those belong to WirePlumber.
- Re-applying after suspend/resume without a USB re-enumeration. It happens anyway if a `new` card/source event fires.
- Per-device stores (serial numbers) and store profiles. There is one store per user.
- Changing WirePlumber/ALSA state restore itself, or the `wireplumber/`/`udev/` files.
- Any UI to view or edit the store beyond the hint. `save` and `forget` are CLI-only.
- Changes to `bin/wave3-reset` and `bin/wave3-meter`.

## Behaviour

### Store

- **S-1 Path.** If `WAVE3_HW_STORE` is set and non-empty, it is the store file path; tests use this. Otherwise the path is `$XDG_STATE_HOME/abduldotdev.wave3/hw.json`, where `XDG_STATE_HOME` falls back to `$HOME/.local/state` when it is unset, empty or not absolute.
- **S-2 Schema.** The store is a JSON object:
  ```json
  {"version": 1, "fields": {"gain_db": 10.0, "clipguard": 1, "lowcut": 1, "hp_db": -20.5, "hp_mute": 0, "direct_monitor": 0, "leds_off": 0, "leds_flip": 0, "gain_lock": 1}}
  ```
  - `fields` may hold any subset of the **stored fields**: `gain_db`, `clipguard`, `lowcut`, `hp_db`, `hp_mute`, `direct_monitor`, `leds_off`, `leds_flip`, `gain_lock`. Only fields the user has set (or `save`d) are present.
  - Values are canonical. dB fields are JSON numbers already clamped and quantised as `set` does (`bin/wave3-hw:197-233`). `direct_monitor` is an integer 0–100 in steps of 5. Booleans are the integers `0`/`1`.
  - Unknown top-level keys and unknown field names are ignored on read. A non-stored field in `fields` (`mute`, `volume_select`, `raw`) is ignored on read and never written.
  - A field with an invalid value is ignored on read, with a `wave3-hw: store: ignoring <field>` line on stderr. Invalid means wrong JSON type, NaN, or a string that `parse_field_value` rejects. An out-of-range number is clamped and quantised like `set`.
- **S-3 Corrupt.** The store is corrupt when the file exists but fails to parse as JSON, is not an object, has `version` ≠ `1`, or has `fields` that is not an object. `apply` then reports `store=corrupt` and exits 7 without writing to the device (A-2). `set` and `save` replace a corrupt store with a fresh one and say so on stderr. `forget` deletes it.
- **S-4 Atomic write.**
  - The directory is created with mode `0700` if missing, and the file is written with mode `0600`.
  - A write goes to a temporary file in the same directory, is flushed and `fsync`ed, then `os.replace`d over `hw.json`. A crash leaves the old file or the new one, never a partial one. No temporary file remains after success or failure.
- **S-5 Serialised.** Store read-modify-write (`set` recording, `save`, `forget`) runs while holding the device lock (B-1), so a concurrent `set` and the watcher cannot lose each other's updates.
- **S-6 Never a snapshot.** Nothing writes the store from device state except `save` (A-3). `status`, `apply` and the watcher never write it, so power-on defaults cannot overwrite the user's choices.

### `wave3-hw` CLI (A)

Usage line: `wave3-hw status | set <field> <value> | apply [--settle SECONDS] [--retries N] | save | forget`.

Exit codes. Codes 0–6 keep their meaning; 7 and 8 are new.

| code | meaning |
|---|---|
| 0 | ok (including no-op) |
| 1 | anything else |
| 2 | usage / bad field / bad value / bad flag |
| 3 | device absent |
| 4 | permission denied (stderr names the udev command, as today) |
| 5 | unsupported API version |
| 6 | read-back mismatch |
| 7 | store corrupt (`apply` only) |
| 8 | device busy: lock wait timed out, or `EBUSY`/`EAGAIN` retries exhausted (B-2) |

Stdout is `key=value`, one per line, in the order listed. Errors go to stderr as `wave3-hw: <text>`.

- **A-1 `set <field> <value>`.** Existing behaviour is kept (`bin/wave3-hw:460-520`), plus:
  - After a verified write of a stored field (S-2), the canonical read-back value is merged into the store (S-4, S-5).
  - Stdout is `<field>=<value>` as today, followed by exactly one of:
    - `saved=yes`: the field is a stored field and the store was written.
    - `saved=no`: the field is not stored (`mute`, `volume_select`).
    - `saved=error`: the device write succeeded but the store write failed. stderr gets `wave3-hw: could not save setting: <reason>`, and the exit code is still `0`, because the device holds the requested value.
  - If the device write fails (exit ≠ 0), the store is not touched and no `saved=` line is printed.
- **A-2 `apply [--settle SECONDS] [--retries N]`.** Restores the store to the device.
  - Flags:
    - `--settle`: a float from 0 to 30, default `0`.
    - `--retries`: an integer from 0 to 10, default `0`.
    - Values out of range or unparsable exit 2.
    - Both `--flag value` and `--flag=value` forms are accepted.
  - **Store load:**
    - Missing store: prints `store=missing`, `changed=`, `reapplied=`, `result=noop`, and exits 0 without opening the device.
    - Corrupt store: prints `store=corrupt`, `changed=`, `reapplied=`, `result=error`, and exits 7 without opening the device.
    - Store with zero usable fields: behaves like missing, except it prints `store=ok`.
  - **Attempt.** Each attempt holds the lock (B-1) for its whole run:
    1. Presence/access check.
    2. Version gate (5.3/5.4).
    3. Read the block.
    4. For each stored field, compare the field's encoded bytes to the store value's encoded bytes.
    5. If any differ, build ONE new block from the read block with only the differing fields re-encoded, write it once, and read it back.
    6. Verify that every stored field's bytes in the read-back equal the store value's bytes.

    Bytes not covered by a stored field are copied from the block just read and never changed: offsets 2–3 (reserved), 4 (`mute`) and 12 (`volume_select`). No attempt writes when nothing differs.
  - **Rounds.** Attempt 0 runs immediately. Then, for `i = 1..N`, the command sleeps `SECONDS` **without holding the lock** and runs attempt `i`. All `N` rounds always run, because a late `SET_CUR` can arrive after an earlier clean round.
  - **Tolerated failures.** When `--retries` > 0, an attempt that ends absent / denied / busy / mismatch does not end the command. The next round tries again.
  - **Stdout:**
    ```
    store=ok
    changed=<comma-separated fields written by attempt 0, in STATUS_FIELDS order; empty if none>
    reapplied=<comma-separated union of fields written by attempts 1..N, same order; empty if none>
    result=applied|noop|absent|denied|unsupported|mismatch|busy|error
    ```
  - **Result and exit code** come from the **last** attempt:
    - A verified attempt gives `applied` if any attempt wrote, else `noop`; the exit code is 0.
    - A failed attempt gives `absent` (3), `denied` (4), `unsupported` (5), `mismatch` (6), `busy` (8) or `error` (1).
  - Each failed attempt also writes one stderr line: `wave3-hw: apply attempt <i>: <reason>`.
  - `apply` never writes the store.
- **A-3 `save`.** Under the lock: presence/access, version gate, then read the block. The store's `fields` are replaced with all nine stored fields decoded from the device, and the store is written (S-4).
  - Stdout is one `<field>=<value>` line per stored field, in `STATUS_FIELDS` order, then `saved=yes`. Exit 0.
  - Device errors use the table codes. A store write failure prints `wave3-hw: could not save setting: <reason>` and exits 1.
- **A-4 `forget`.** Under the lock, deletes the store file. No device access, so it works with the mic unplugged.
  - Stdout: `forgotten=yes` if the file existed, `forgotten=no` if not. Exit 0.
  - An unlink error other than "not found" exits 1.
- **A-5 `volume_select` never persisted.** `set volume_select` still works and prints `saved=no`. `save` never includes it, and `apply` never writes byte 12.
- **A-6 Watcher sequence.** `wave3-watch` calls `wave3-hw apply --settle 2.5 --retries 2`: an immediate attempt, then checks at about +2.5 s and +5 s, each re-applying any drift. With `gain_lock` stored as 1, the first attempt's single write sets the lock together with the gain, so a later OS `SET_CUR` is ignored by the firmware. With `gain_lock` stored as 0, the rounds put the stored gain back after a late ALSA restore. After the last round, later OS volume changes are not fought.

### `wave3-watch` (A)

- **W-1 Binary.** Runs `${WAVE3_HW:-$HERE/wave3-hw}`, where `$HERE` is the resolved script dir as used for `wave3-reset` (`bin/wave3-watch:11-12`). No new `~/.local/bin` link is needed.
- **W-2 When.** An apply runs once at startup, and on each `Event 'new' on card #…` or `Event 'new' on source #…` line (the same lines that trigger reset today). `change` and `remove` events never trigger it.
- **W-3 Non-blocking.** Apply runs in the background. Reset handling (`--ensure-default`) keeps its current timing and count: the existing test "runs at start and once per new source/card event only" still holds.
- **W-4 Rate limit.**
  - A new apply is not started while a previous one is still running.
  - A new apply is not started within `${WAVE3_APPLY_INTERVAL:-5}` seconds of the previous apply's start. The value is an integer ≥ 0, and `0` disables only this time window.
  - Events suppressed this way are dropped, not queued. The in-flight apply's settle rounds cover the burst of card+source events a replug produces.
- **W-5 Logging.** Each apply writes exactly one line to stderr (the journal) when it finishes: `wave3-watch: apply rc=<rc> <stdout lines joined by single spaces>`, e.g. `wave3-watch: apply rc=0 store=ok changed=gain_db,lowcut,gain_lock reapplied= result=applied`. `wave3-hw`'s own stderr is passed through as-is. A skipped apply logs nothing.
- **W-6 Never crash-loops on apply.** A missing or non-executable `wave3-hw`, a missing `python3`, or any non-zero apply rc never makes the watcher exit, and never skips the reset.
  - The only exit stays "`pactl subscribe` ended", with exit 1 and the existing message.
  - Before exiting, the watcher waits for an in-flight apply to finish, so its log line is not lost.
- **W-7 Unit.** `systemd/wave3-watch.service` keeps `ExecStart`/`Restart`. `Description=` becomes `Keep the Elgato Wave:3 as the default microphone and restore its settings`. No other change is needed.

### Busy-safe access (B)

- **B-1 One lock.** `status`, `set`, `apply` (per attempt), `save` and `forget` all take the existing `file_lock()` at `$XDG_RUNTIME_DIR/wave3-hw.lock` (fallback `/tmp`).
  - Lock acquisition gives up after at most 2 s (non-blocking attempts with short sleeps).
  - On timeout, `status` prints `error=busy`. `set`, `apply` and `save` treat it as busy (exit 8 / `result=busy`). `forget` exits 8.
  - If the lock file cannot be opened, the command proceeds unlocked, as today.
- **B-2 Retry.** Every USB transport operation retries on `OSError` with `errno` in {`EBUSY`, `EAGAIN`}: the device-node open, each version, config-read and config-write control transfer, and the presence/access probe.
  - Backoff is exponential starting at 10 ms (10, 20, 40, 80, 160, 320 ms), with at most 7 attempts and about 1 s total sleep per operation.
  - `EACCES`/`EPERM` still map to denied and `ENOENT`/`ENODEV` to absent, with no retry. When retries run out, the operation is busy.
  - `FakeTransport` goes through the same retry path (see T-4).
- **B-3 Status output on failure.**
  - On success, output is unchanged (`bin/wave3-hw:443-453`). On absent or denied, output is unchanged (`bin/wave3-hw:424-437`).
  - On busy (lock timeout or retries exhausted), stdout is exactly one line, `error=busy`.
  - On any other unexpected failure, stdout is exactly one line, `error=<one-line message>` with newlines replaced by spaces.
  - `status` always exits 0.
  - No partial field lines are ever printed before an `error=` line.
- **B-4 Model keeps the last good state.**
  - `Model.parseHwStatus` gains two fields:
    - `error` (string): the `error=` value, `""` if none.
    - `transient` (bool): true when the output has an `error=` line and no `present=` line.
  - A new `Model.mergeHwStatus(prev, next)`:
    - If `next.transient` and `prev` is ready (`prev.hwReady`), it returns a copy of `prev` with `stale: true` and `error: next.error`.
    - Otherwise it returns `next`, with `stale: false`.
    - Only a definitive status changes the mode: `present=no`, `access=denied`, `supported=no`, or a successful read.
  - `Widget.qml` assigns `root.hwStatus = Model.mergeHwStatus(root.hwStatus, Model.parseHwStatus(text))`.
  - A transient error with no previous good state stays not-ready, as today.
  - The popup may dim hardware sections while `stale` is true. That is optional, and it must not hide them.
- **B-5 Mute policy.** Hardware `mute` is **not** persisted and **not** restored. A mic that comes back muted after a reboot or replug is surprising and easy to miss in a call. `set mute` prints `saved=no`. The README says so.
- **B-6 Less polling.**
  - A widget whose popup is closed runs `wave3-hw status` at most once every 30 s. The bar icon still needs hardware `mute`. `wave3-reset --status` stays on the 10 s timer.
  - A widget whose popup is open polls both on open and every 3 s, as today.
  - `wave3-hw status` is not started while that widget's `hwSetProc` is running or `pendingHwSets` is non-empty. The read is deferred until the queue drains; `pumpHwSets` already calls `refresh()` when empty (`Widget.qml:104-113`).
  - At most one `wave3-hw status` per widget runs at a time (unchanged).

### Popup (A)

- **P-1 Parse set output.** A new `Model.parseHwSetOutput(text)` returns `{ field: string, value: string, saved: "yes"|"no"|"error"|"" }` from `set` stdout. `field`/`value` come from the first line whose key is not `saved`.
- **P-2 Saved hint.**
  - `Widget.qml` collects `hwSetProc` stdout. On exit 0 with `saved === "yes"`, it shows the hint `Saved · restores on reconnect` (text exported as `Model.SAVED_HINT`) for 4 s. Each new saved change restarts the 4 s.
  - The hint is passed to `Wave3Popup.qml` as a string property and shown as small muted text near the existing error text (`Wave3Popup.qml:949-957`). It is hidden when empty.
  - `saved === "error"` sets `errorText` to `Changed, but could not save it for reconnect`, using the existing 6 s `errorTimer`.
  - `saved === "no"` shows nothing.
- **P-3 Unchanged otherwise.** Queueing, debounce, the latest value per field, and the error display on non-zero exit stay as they are.

### Test requirements (cited by the acceptance criteria)

- **T-1 Restore from the observed power-on block.**
  - Fake `config` = `00 28 00 ec 00 01 00 80 eb 00 00 00 02 00 00 00`.
  - Store = `{gain_db:10.0, clipguard:1, lowcut:1, hp_db:-20.5, hp_mute:0, direct_monitor:0, leds_off:0, leds_flip:0, gain_lock:1}`.
  - `apply` exits 0 and prints `store=ok`, `changed=gain_db,lowcut,gain_lock`, `reapplied=`, `result=applied`.
  - The config is then `00 0a 00 ec 00 01 01 80 eb 00 00 00 02 00 00 01`: bytes 2–3 are `00 ec`, byte 12 is `02`, byte 4 is `00`.
  - The `writes` log has exactly 1 entry.
- **T-2 No-op.** A second `apply` prints `changed=`, `result=noop`, exits 0, and adds no `writes` entry.
- **T-3 Store states.**
  - Missing store: `store=missing`, `result=noop`, exit 0. Holds even with the fake dir absent, since the device is not opened.
  - Corrupt store (`{`, `[]`, `{"version":2,"fields":{}}`): exit 7, `store=corrupt`, and the config is unchanged.
  - An invalid field value (`"gain_db":"abc"`) is skipped with a stderr line while the other fields apply.
  - `volume_select`/`mute` keys in the store are ignored (byte 4 and byte 12 unchanged).
  - Device absent: exit 3. Denied: exit 4. Unsupported version: exit 5. `readonly`: exit 6.
- **T-4 Fake transport hooks** (only in `FakeTransport`):
  - `<fake>/writes`: one line appended per `write_config`.
  - `<fake>/busy`: holds an integer N. Each fake operation, while N>0, decrements it and raises `OSError(EBUSY)`.
  - `<fake>/drift`: a hex block that replaces `config` on the second `read_config` after the first `write_config`, then is deleted. This simulates a late `SET_CUR` after the read-back.

  Cases:
  - `busy`=3 → `status` shows `access=ok`, and `set` succeeds.
  - `busy`=1000 → `status` prints exactly `error=busy` (rc 0), and `set` exits 8.
  - `drift` with gain 40 dB plus `apply --settle 0.1 --retries 1` → `reapplied=gain_db`, `result=applied`, and the final config equals the store.
  - Bad flags (`--settle -1`, `--settle 31`, `--retries 11`, `--settle x`) exit 2.
- **T-5 Record on set.**
  - `set lowcut 1` prints `lowcut=1` then `saved=yes`. The store has `fields.lowcut == 1` and mode `0600`, its directory has mode `0700`, and no temp file remains.
  - `set gain_db 12.3` stores `12.5`.
  - `set mute 1` and `set volume_select mix` print `saved=no` and add no key.
  - A failed `set` (absent) leaves the store unchanged and prints no `saved=`.
  - A store path whose parent is a regular file gives `saved=error` with exit 0.
  - `set` over a corrupt store replaces it with a valid one.
- **T-6 Save/forget.**
  - `save` writes all nine stored fields decoded from the fake and prints nine `field=` lines plus `saved=yes`. It never writes `mute`/`volume_select`.
  - `forget` prints `forgotten=yes` and removes the file. A second `forget` prints `forgotten=no`. Both exit 0.
- **T-7 Watcher** (stub `WAVE3_HW` that logs its argv and prints canned output):
  - One apply with `apply --settle 2.5 --retries 2` at start.
  - The existing event fixture with the default interval still gives exactly one apply (rate-limited) and three resets.
  - With `WAVE3_APPLY_INTERVAL=0` and events arriving after the previous apply finished, a later `new card` line gives a second apply.
  - A stub that exits 3, 1, or is missing keeps the watcher running: resets still happen, and the exit is still the non-zero "subscribe ended".
  - Each apply logs one `wave3-watch: apply rc=` line to stderr.
- **T-8 Model.**
  - After a good status, merging `error=busy` keeps `hwReady === true` and the old field values, with `stale === true`.
  - After a good status, `present=no`, `access=denied` or `supported=no` each give `hwReady === false`.
  - With no previous good status, `error=busy` gives `hwReady === false`.
  - A following good status gives `stale === false`.
  - `parseHwSetOutput` reads `lowcut=1\nsaved=yes` / `saved=no` / `saved=error` / empty output.

## Acceptance criteria

1. `grep -n 'def cmd_apply\|def cmd_save\|def cmd_forget' bin/wave3-hw` finds all three, and `bin/wave3-hw` with no args prints the A-section usage line and exits 2.
2. `python3 -m unittest discover -s tests -p 'test_*.py'` passes and includes T-1..T-6 (inspect: test names mention restore-from-power-on, noop, missing/corrupt store, record-on-set, save/forget, busy retry, drift/settle).
3. `node --test tests/` passes and includes T-8.
4. `bash tests/scripts.test.sh` passes and includes T-7. The existing watcher checks still pass unchanged.
5. `/usr/lib/qt6/bin/qmllint Widget.qml` and `/usr/lib/qt6/bin/qmllint Wave3Popup.qml` show no warning kinds beyond the pre-change baseline (unresolved `qs.*`/Quickshell imports and types).
6. `grep -nE '=>|\blet\b|\bconst\b' Model.js` is empty (ES5 only).
7. Inspection of `bin/wave3-hw`:
   - Every one of `status`, `set`, `apply`, `save` and `forget` runs its device and store access inside the lock.
   - `apply`'s sleep between rounds is outside the lock.
   - No code path writes byte 4 or byte 12 from `apply`.
   - No code path writes the store from `status` or `apply`.
8. Unit tests never touch the real store: `grep -n WAVE3_HW_STORE tests/test_wave3_hw.py tests/live-hw.sh` shows it set in both.
9. Live, with the udev rule installed and the output pasted in the supervisor report:
   - `for i in $(seq 20); do bin/wave3-hw status & done | grep -c '^access=ok'` prints `20`, and nothing prints `error=`.
   - `WAVE3_HW_STORE=$(mktemp -u) tests/live-hw.sh` exits 0.
10. Live restore check, with the output pasted:
    1. Record the `raw=` block.
    2. Using a temp `WAVE3_HW_STORE`, `set` one field (e.g. `lowcut`) to value X.
    3. `set` it to Y ≠ X with `WAVE3_HW_STORE=/dev/null/x` so X stays stored. `saved=error` is expected there.

## Open questions

5. **`stale` visual.** *Default:* no visual change is required. Dimming is allowed but must not hide controls.
6. **Store scoped per device serial?** *Default:* no, one store per user (out of scope).
7. **Journal noise.** Every non-skipped apply logs a line, including `store=missing`. *Default:* keep. It is at most one line per 5 s, and only on device events.
